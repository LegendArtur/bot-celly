This is the canonical roadmap. It is directional, not a set of commitments; the
[changelog](/changelog) records what has actually shipped and
[Limitations](/reference/limitations) covers what the current release does not
do.

- **React dashboard.** Replace the server-rendered loopback admin page with a
  React-based bot dashboard: live project cards, streaming logs, cost and budget
  views, the audit trail, and approvals in one UI. Loopback-only by default, like
  the current [admin page](/guides/operations#admin-page).
- **Thread title updater and live thread stats.** Keep each Discord thread's
  title in sync with its session (renamed from the latest prompt or a generated
  summary), and surface live per-thread stats — run state, model and agent,
  queued prompts, tokens, and cost — in the thread or channel.
- **Image output.** Post images the agent produces — screenshots, diagrams,
  rendered output — into the thread, alongside streamed text.
- **Cloud sandboxes and hosted deployment.** Run projects in cloud sandboxes and
  deploy Celly as a hosted service, so no local host is required.
- **Per-user GitHub connect.** A Discord `/connect github` device-flow OAuth
  handshake so each user links their own GitHub, replacing the single shared host
  `GITHUB_TOKEN` and removing the need to edit `.env`.
- **Image and voice input.** Send images and voice messages as prompts, not just
  text and text attachments.
- **Single OpenCode API surface.** Celly talks to OpenCode through both its v1
  and v2 SDK surfaces today (sessions and config on v1; permission, questions,
  and global config on v2). Migrate every call to the v2 surface and remove the
  v1 client, so the version split lives only in upstream event names rather than
  in Celly's code.
