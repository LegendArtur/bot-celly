This page is the single source of truth for Celly's operational surfaces: the
admin page, logs, log rotation, backups, and restore. The
[deployment guides](/guides/deployment) link here instead of repeating it.

## Admin page

<Snippet file="snippets/admin-page.mdx" />

The page trusts anything on the host, so local code shares the host trust
boundary. See [Security](/reference/security) for the threat model.

An owner can post the console URL to Discord with `/dashboard`. The link only
opens from the Celly host or an SSH tunnel; `ADMIN_PORT=0` reports it disabled.

### What the console shows

- **Projects.** Live cards with sandbox status, host port, sandbox name, last
  activity, spend, tokens, and session count, each with Start / Stop / Restart
  and Remove actions.
- **New project.** Create a directory under `PROJECTS_ROOT`, optionally cloning
  an `https://` repository — the same operation as `/project create`.
- **Usage and cost.** Cumulative spend and tokens, with prompt/completion and
  cache read/write breakdowns.
- **Audit.** The recent `audit.jsonl` entries.
- **Logs and sessions.** Per-project redacted log tails and the project's
  sessions, each with its terminal attach command.

The page updates live over server-sent events, so it does not need a manual
refresh. Removing a project stops the sandbox and deletes the Discord channel,
but keeps the host directory.

### Endpoints

The JSON API is the surface the page is built on:

- `GET /` — HTML console.
- `GET /api/projects` — registry list: `[{ channelId, path, status }]`.
- `POST /api/projects` — create from JSON `{ "name", "path" }`. The path must
  resolve inside `PROJECTS_ROOT` and pass the
  [path denylist](/guides/configuration#projects_root-and-path-containment); the
  existing create saga runs unchanged. Returns `{ channelId, status }`, `409`
  when the path is already registered, and `400`/`403` for an invalid or
  disallowed path.
- `DELETE /api/projects/<channelId>` — remove (keeps the host directory); `204`
  on success, `404` when unknown.
- `POST /api/projects/<channelId>/start|stop|restart`.
- `GET /api/health` — `200` while the server is up.
- `GET /api/logs/<channelId>?lines=200` — redacted log tail (capped at `2000`).
- `GET /api/audit?limit=100` — recent audit entries (capped at `1000`).
- `GET /events` — server-sent event stream of live console fragments.
- `GET /assets/<name>` — vendored console assets.

`status` uses registryd's vocabulary: `ready`, `provisioning`, `failed`, or
`degraded` (`running`→`ready`, `starting`/`creating`→`provisioning`,
`error`/`failed`→`failed`, `stopped`→`degraded`).

The HTML page additionally uses `/partials/*` fragment routes. Those are an
implementation detail of the console, not a stable API.

## Logs

Celly logs to the console (colored on a TTY) and to `DATA_DIR/bot.log` as JSONL.
Each project's supervised `opencode serve` child appends to
`DATA_DIR/logs/<project>.log`. `LOG_LEVEL` (`debug`, `info`, `warn`, `error`)
sets console verbosity. Tokens, passwords, and `Authorization` headers are
redacted before they reach either sink.

When a pending approval or question is dropped before a member decides it, the
`WARN` line records the `threadId`, `sessionId`, `requestId`, and a `cause`:
`run-ended`, `server-resolved`, `permission-replied`, `question-replied`,
`question-rejected`, or `timeout`. Matching that `requestId` against a
"this request is no longer active" reply from an approval click shows why the
request was gone. Pending approvals live in memory only, so a bot restart drops
every one of them; those drops leave no log line.

## Session cleanup

Archiving a managed thread prompts in its parent channel to remove the session
(see [Archived threads](/reference/commands#archived-threads)). Choosing
**Remove session** deletes the OpenCode session and the thread record and folds
its usage into the channel totals, so `/cost` and the admin usage figures stay
accurate. Removals are audited with `kind: "session"`.

### Restore

Stop the bot first so the database is not open while it is replaced.

<Tabs>
  <Tab title="Windows">
    ```powershell
    Stop-ScheduledTask -TaskName Celly
    Copy-Item data\backups\bot-<ISO>.db data\bot.db -Force
    Start-ScheduledTask -TaskName Celly
    ```
  </Tab>
  <Tab title="Linux">
    ```bash
    systemctl --user stop celly
    cp data/backups/bot-<ISO>.db data/bot.db
    systemctl --user start celly
    ```
  </Tab>
</Tabs>
